# COCO Teacher production phase

The new `coco_s4.phase_teacher` entrypoint calls the already CPU-validated strict train-only Teacher directly. The release binds committed source bytes, the frozen configuration, actual native dependencies, and the accepted official metadata/image manifests. No accepted image audit or old experiment is repeated.

The same production path is used for a bounded ten-native-batch CUDA smoke, with the full 25K train loader, batch36/workers16/640/cacheTrue/native AMP SGD. A native between-batch stop ends this non-result smoke and saves its real checkpoint and audit. The pre-update loss comparison separately instantiates the pinned native DetectionModel, copies the identical random initialization and uses the identical input/GT tensors. Official metrics and ingest remain disabled. No full training result is implied by the smoke.

AMP preflight reuses the accepted historical random-model FP32/autocast selfcheck, rather than the upstream reference-YOLO26 weight download. It checks finite raw predictions and tolerance0.5, restores model mode and never updates parameters. Native GradScaler, SGD, clipping, legal overflow skips, scheduler and augmentation remain inherited. This preflight choice is explicit in the phase specification and scientific review scope.

The single `coco_s4.serial` controller performs predecessor/capacity checks, the bounded smoke, waits for one exact scientific closure receipt, and then starts the authorized fresh Teacher200 automatically. Teacher training cannot construct a validation-image loader or call a validation forward, including native final-epoch and final_eval dispatches. last@200 and full native training state are retained; no optimizer stripping or interrupted-worker exact-resume claim is made.

Later phases have named ordered slots in this same controller. They require immutable, independently validated phase releases, bound to the accepted preceding receipt. Their implementation and acceptance are still open; no future phase or scientific gate is represented as already passed. This permits constructing actual COCO statistics after a real Teacher exists, without changing the active Teacher source or creating another scheduler. The next phase is a separate read-only official full-val2017 evaluation of the fixed Teacher last@200, with no checkpoint selection or method-statistics input from val.
