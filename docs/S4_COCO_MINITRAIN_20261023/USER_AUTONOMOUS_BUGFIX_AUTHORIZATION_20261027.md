以下内容属于不可擅自修改的科学方法。

### 1. 目标类别与数据

COCO80：

- Target：Person，ID=0；
- Non-target：79 类；

- 不跳过合法 GT；

### 2. 原始空间预算

- Person 独占区域：8/255；
- Person 与非目标 GT 重叠区域：4/255；
- Person 框外：0。

不得采用 S4-TFSS-Full 的全目标框 8/255 方案。

### 3. TFSS-Utility

保留原始公式：

W_U = 1 - 0.15 × R_nt × (1 - Q_t)

其中：

- eta=0.85；
- Q_t 保留原始目标特征归因定义；
- R_nt 保留原始非目标 GT 检测敏感度定义；
- TFSS 必须真正参与 Fourier 优化；
- Frozen 与 Adaptive 使用经过相同空间调控的实际加噪图像；
- 训练与导出的扰动构造保持一致。

不得为了避免计算异常而关闭 TFSS、使用常数权重或将无效梯度强行替换为零。

### 4. 语义方法

保留：

- Strict TSFL；
- P5 目标特异性通道选择；
- Contextual Background Prototypes；
- Safe-BG；
- K=8 背景原型；
- Top-3 非目标语义子空间；
- rank=8；
- removal_alpha=0.5；
- 原有范数恢复机制；
- L_BG；
- L_rel；
- L_orth；
- L_ret。

COCO 中 TSFL 选择出的 39 个通道应保留。

允许实现动态维度兼容，但不得修改原有特征筛选规则。

P3 与 P5 的特征坐标必须正确对应，不能混用。

### 5. 扰动优化

保留：

- 原始共享 Fourier 参数化；
- 原始 EOT；
- 原始优化目标与损失权重；
- 原始 Frozen/Adaptive 双分支；
- 一步可微虚拟更新；
- 原始 Optimizer；
- 原始 Scheduler；
- 原始预算和正则项。

不得引入新的 U-Net、GAN、Diffusion 或其他生成器。

## 五、每次 Bug 的标准自主修复流程

今后遇到 Bug，请默认执行以下流程，不要直接暂停等待我指挥。

### Step 1：异常捕获

记录：

- 错误信息；
- RunID；
- PID；
- Git Commit；
- 数据集身份；
- 配置；
- Checkpoint；
- 当前处理的样本；
- GT；
- 相关张量形状；
- CUDA 状态；
- 失败前最后一个有效计算步骤。

### Step 2：根因分析

判断属于：

- 数据错误；
- 标注错误；
- 坐标错误；
- 计算错误；
- 数值稳定性错误；
- 缓存错误；
- 原始方法不适配；
- 真实的科学方法定义缺口。

不得把所有异常都归因于数值精度。

不得为了修复而反复尝试没有理论依据的参数。

### Step 3：最小复现

尽可能使用原始失败样本、真实 Teacher 和相同配置复现问题。

如果可以通过 CPU 测试定位错误，应优先执行 CPU 测试。

但真实 GPU 路径有必要验证时，不得仅以 CPU 测试代替。

### Step 4：修复分类

判定为 Level A、Level B 或 Level C。

写入修复记录。

### Step 5：隔离修复

在独立 Git 分支或 worktree 中修改。

不要直接覆盖正在运行的实验代码。

### Step 6：自动测试

至少检查：

- 修复样本通过；
- 原有正常样本不回归；
- S4 方法一致性；
- Fourier 梯度；
- Frozen/Adaptive；
- TFSS；
- Safe-BG；
- GT 完整性；
- 扰动预算；
- 训练/导出一致性；
- VOC20 原始路径。

### Step 7：发布

完成 Git Commit。

成功 Push 后核查远端 SHA。

不能将本地提交成功当作 GitHub 发布成功。

### Step 8：恢复决策

如果属于 Level A/B，并且所有验收条件满足，可以自动恢复正式实验。

如果属于 Level C，且改变了核心方法，应保留正式 Original S4 阻塞状态，完成独立实验协议说明，不得自动将新定义冒充原方法。
